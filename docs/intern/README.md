# Interne Arbeitsdokumente

Arbeitsprotokolle aus der Entwicklung — bewusst im Repo behalten, weil sie
belegen, *warum* Dinge so gebaut sind, und nicht nur *dass* sie gebaut sind.
Für das Verständnis des Systems sind sie nicht nötig: dafür reichen
`README.md`, `docs/testmatrix.md` und `docs/abschlussbericht.md`.

- **KONTEXT.md** — laufendes Sitzungsprotokoll: was gebaut wurde, welche
  Architekturentscheidungen getroffen und welche Alternativen verworfen
  wurden. Die primäre Begründungsquelle, auf die viele Code-Kommentare mit
  „siehe KONTEXT.md" verweisen.
- **RALPH-PROGRESS.md** — Protokoll eines mehrstufigen Härtungsdurchlaufs
  (Backlog-Punkte, gefundene Befunde, jeweiliger Fix). Code-Kommentare
  verweisen mit „RALPH-PROGRESS.md Backlog #n" auf die einzelnen Punkte.

Beide Dateien sind lang und zum Nachschlagen gedacht, nicht zum Durchlesen —
am besten gezielt nach einem Stichwort greppen.
